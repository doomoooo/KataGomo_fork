## 根因修复：legacy stream

原 `benchmarknn` 的 CUDA 自定义 kernel（RMSNorm、RoPE、SwiGLU、residual
等）全部落在 legacy stream（Nsys stream 7），只有 cuDNN/cuBLAS 在各自
per-thread stream 上，导致双流没有真正并行。

原因：`cudahelpers.cu` 由 nvcc 编译时会在用户代码之前隐式包含
`cuda_runtime.h`，`cudaincludes.h` 里的
`CUDA_API_PER_THREAD_DEFAULT_STREAM` 定义太晚，对 `<<<>>>` 不生效。

修复：在 [CMakeLists.txt](/workspace/katago/cpp/CMakeLists.txt) 的 CUDA
分支增加 `add_compile_definitions(CUDA_API_PER_THREAD_DEFAULT_STREAM)`。

修复后 Nsys 证据：
[gpu0-b23-fixed-s2.nsys-rep](/workspace/results/shared/baselines/initial/profiles/gpu0-b23-fixed-s2.nsys-rep)
显示两个 server 的自定义 kernel 与 cuDNN/cuBLAS kernel 分别分布在
stream 76 和 82，不再共用 legacy stream。

## 左侧补充确认（B10–B13）

为确认平台左侧入口，CUDA 用 3×300、TensorRT 用 3×1000 补测 B10/B11/B12。

| GPU | backend | B10 | B11 | B12 | B13 | 左侧入口 |
|---|---|---:|---:|---:|---:|---|
| RTX 4090 | CUDA | 1727.5 | 1857.9 | 1871.6 | 1876.3 | B11/B12 |
| RTX 4090 | TensorRT | 2403.0 | 2435.0 | 2478.1 | 2542.9 | B13 |
| RTX 5090 D | CUDA | 2359.2 | 2398.8 | 2393.7 | 2517.5 | B13 |
| RTX 5090 D | TensorRT | 3072.2 | 3235.1 | 3239.4 | 3258.8 | B11/B12 |

结论：CUDA 与 TensorRT 的平台没有完全对齐，左侧入口最多差 1 个 batch；
**B13 是四个 backend/GPU 组合都能落进去的公共点**。若允许按后端分别取左侧，
TRT 5090D 可降到 B11（比 B13 低约 0.7%），但会破坏跨后端一致性。

## 复现命令

```bash
# CUDA 4090, B13
/workspace/katago/build-cuda/katago benchmarknn \
  -config /workspace/bench-cuda-gpu0-4090-s2.cfg \
  -model /workspace/models/b11c768h12nbt3tflrs-fson-silu.bin.gz \
  -iterations 300 -warmup 10 -batch-size 13 -json

# CUDA 5090D, B13
/workspace/katago/build-cuda/katago benchmarknn \
  -config /workspace/bench-cuda-gpu2-5090d-s2.cfg \
  -model /workspace/models/b11c768h12nbt3tflrs-fson-silu.bin.gz \
  -iterations 300 -warmup 10 -batch-size 13 -json

# TensorRT 4090, B13
/workspace/katago/build-trt/katago benchmarknn \
  -config /workspace/bench-trt-gpu0-4090-s2.cfg \
```
