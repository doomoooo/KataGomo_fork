## Requested latest-stack target

The user requested that dependency management on this branch use the latest
stable software stack.  Discovery on 2026-08-18 found:

- highest native-wheel-complete Python: CPython 3.14.7 from
  python-build-standalone release `20260814`; archive SHA-256
  `cefba034445d2875408d1fd4d5700ae6731563aeb54dcb39fd8164ab5c457533`;
- latest stable CUDA toolkit: 13.3 Update 1 (`cuda-toolkit==13.3.1`, nvcc/CRT/
  NVVM 13.3.73), minimum driver 610.43.02;
- latest NVIDIA cuDNN package: 9.25.0.15 (available from NVIDIA's Python
  index and Ubuntu NVIDIA repository);
- latest stable PyTorch: 2.13.0; its newest official GPU wheel is
  `2.13.0+cu132` because no cu133 wheel exists;
- latest TensorRT available from the NVIDIA repository: 11.2.1.2 for CUDA
  13.3;
- current published generator packages: TileLang 0.1.13, Quack 0.6.4,
  CUTLASS DSL 4.7.0, Triton 3.7.1;
- current upstream CUTLASS and FlashAttention remain source inputs selected by
  `HEAD` and require `KATAGO_REFRESH_SOURCES=1` to refresh cached checkouts.

There is no metadata-clean single Python environment containing every
individually latest package:

1. PyTorch `2.13.0+cu132` pins CUDA toolkit 13.2.1, cuDNN 9.20.0.48,
   cuSPARSELt 0.8.1, NCCL 2.29.7, and NVSHMEM 3.4.5.
2. TileLang 0.1.13 requires TVM-FFI `<0.1.13` and z3-solver `<4.15.5`, so
   TVM-FFI 0.1.12 and z3-solver 4.15.4.0 are the newest compatible choices.
3. Quack 0.6.4 pins CUTLASS DSL 4.6.2 while the latest DSL is 4.7.0; the old
   branch already carries an explicit, smoke-tested waiver for this pair.
4. `cuda-python==13.3.1` requires `cuda-core~=1.0.0`, so cuda-core 1.0.1 is
   the newest compatible value rather than independently latest 1.1.1.
5. SymPy 1.14 requires mpmath `<1.4`, so mpmath 1.3.0 remains required.

The recommended implementation of the user's latest-stack directive is an
explicitly split and recorded boundary:

- native inference/toolchain: CUDA 13.3.1 + cuDNN 9.25.0.15 + TensorRT
  11.2.1.2;
- Python/code-generation runtime: CPython 3.14.7 + latest PyTorch
  2.13.0+cu132 and the highest compatible TileLang/Quack/CUTLASS DSL closure.

Do not silently broaden `pip check` waivers to pretend that PyTorch has a
cu133 binary.  Record the build CUDA and PyTorch wheel CUDA separately and
validate source generation, imports, compile, GPU execution, and correctness
at that boundary.  An alternative lower-risk unified stack is CUDA 13.2.1 +
cuDNN 9.20 from the exact PyTorch cu132 closure, but it does not fulfill the
literal latest-native-stack request.

This tar is useful as the requested B300 10.16.1 comparison baseline, but it
is not the latest TensorRT selected for the final latest-native stack.  It

the root filesystem.  Extract in `/dev/shm`, or select only headers,
`libnvinfer.so*`, `libnvonnxparser.so*`,
`libnvinfer_builder_resource_sm100.so*`, and
`libnvinfer_builder_resource_ptx.so*`.  Static libraries and unrelated
architecture/Windows resources account for most of the archive.

The TensorRT backend also needs C++ protobuf headers, library, and `protoc`;
the Python `protobuf` wheel is insufficient.  This prerequisite was not yet
installed.  Build in a separate directory and verify `ldd`, `katago version`,
the TensorRT sandbox, and a B4 model smoke before scanning.
